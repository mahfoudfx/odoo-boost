## Odoo 15 Specific Notes & API Highlights

### Key Architecture Changes
- **OWL 1.x**: OWL coexists with legacy web-client code. Components extend `owl.Component`.
- **Assets Bundle Revolution**: Assets moved from XML templates to `assets` dictionary in `__manifest__.py`:
  ```python
  'assets': {
      'web.assets_backend': [
          'my_module/static/src/js/**/*.js',
          'my_module/static/src/scss/**/*.scss',
          'my_module/static/src/xml/**/*.xml',
      ],
  }
  ```
- **Command Class Introduced**: `from odoo.fields import Command` introduced as cleaner alternative to `(0, 0, ...)` tuples:
  ```python
  from odoo.fields import Command

  record.write({"line_ids": [Command.create({"name": "New"})]})
  ```
- **ORM & Views**: `attrs` dictionary syntax remains standard.


### Audited compatibility boundaries
- Use the Odoo 15 Owl/global API and `owl="1"` on Owl templates; modern imports
  are not a universal Odoo 15 recipe. JS modules opt in with the module pragma.
- Preserve cursor-based hook signatures from the matching manifest reference;
  later versions use an environment argument.
- Stock execution uses `qty_done`; cache guidance uses the legacy invalidation
  API where newer helpers are unavailable.
- Access declarations still use `ir.model.access` plus `ir.rule`; the audited
  unified `ir.access` model belongs to 20.

Official baseline: [Odoo 15 developer reference](https://github.com/odoo/documentation/tree/15.0/content/developer).
The version-audit reports record precise per-claim evidence and limits.
