## Odoo 20 Specific Notes

Odoo 20.0 is registered explicitly and inherits unchanged Odoo 19 facts. These
deltas are grounded in the Odoo 20.0 source and its official `skills/` library.
They do not make master-only behavior safe for 20.0 without checking that branch.

### Runtime baseline

- Odoo 20.0 declares Python 3.12 through 3.14 and PostgreSQL 16 or newer.
- Controller route types are `http`, `jsonrpc`, and `json2`. The old `json`
  spelling remains a deprecated Odoo 19 alias; use `jsonrpc` in new code.
- A route using `auth="bearer"` must define an appropriate `bearer_scope`.

### ORM and security APIs

The official v20 skill set emphasizes the APIs below. This list does not claim
that every API was first introduced in v20; it records their verified v20 use.

- Compose domains with `odoo.fields.Domain` when accepting or combining dynamic
  conditions. Never concatenate an untrusted domain onto a security domain.
- Model methods are private by default. Public methods are remotely callable;
  validate their recordsets and arguments. `@api.private` can keep a public
  Python name out of RPC when renaming would break internal callers.
- Review `related` fields carrying secrets or personal data: related computes
  use elevated access by default. Set `related_sudo=False` where the user must
  retain normal access checks.
- Use `odoo.tools.file_open` for addon resources and `odoo.tools.consteq` for
  secret comparisons. Do not deserialize data with `pickle`.

### Contribution scope

Odoo's official skills are primarily house rules for work inside the upstream
community and enterprise repositories. Their stable-branch restrictions,
cross-repository review, file layout, XML-ID naming, and web styling conventions
are not automatically OCA or customer-addon rules. Load the
`odoo_core_contribution` skill only when the target is Odoo's own source tree.

Verify evolving framework details against the exact 20.0 checkout. Master is
currently a later development series and is evidence only when the same change
exists on the 20.0 branch.

The official skill files shipped on 20.0 currently also describe some changes
explicitly as **master-only**, including unified `ir.access` declarations and
the replacement of `_sql_constraints`. Odoo Boost deliberately does not apply
those claims to 20.0. Inspect the branch source before migrating ACL files,
constraints, indexes, or other persistent metadata.
