## Odoo 18 Specific Notes & API Highlights

### Key Changes in Odoo 18
- Treat Odoo 17 guidance as a starting point; apply the explicit Odoo 18 deltas below.
- **`<list>` is Mandatory in XML Views**: `<tree>` is replaced by `<list>`. All list views must use `<list string="...">...</list>`.
- **Inline Expressions are Mandatory**: `attrs` dictionary syntax is completely removed and will crash view compilation.
  ```xml
  <!-- Required in v18 -->
  <field name="order_line" readonly="state in ('done', 'cancel')"/>
  ```
- **Domain Operators**: Verify supported domain operators in the target ORM before changing queries.
- **Controller Responses**: Return a dictionary from JSON-RPC routes; use `request.make_json_response(data)` when an HTTP route needs a JSON response.
- **Portal UX**: Redesigned portal frontend with modernized Bootstrap 5 templates.

### Important v18 Patterns
- **Relational Field Manipulation**:
  ```python
  from odoo.fields import Command

  record.write(
      {
          "line_ids": [
              Command.create({"name": "New line", "qty": 1}),
              Command.update(line_id, {"qty": 5}),
              Command.delete(line_id),
          ]
      }
  )
  ```
- **Display Name**:
  ```python
  @api.depends("name")
  def _compute_display_name(self):
      for rec in self:
          rec.display_name = rec.name or _("Untitled")
  ```

### Removed in v18
- `attrs` dict syntax is completely gone.
- `<tree>` view root tag is replaced by `<list>`.


### Audited compatibility boundaries
- Native modules in `static/src` and `static/tests` are transformed automatically.
- Scheduler batching documents `_notify_progress`; do not copy the Odoo 19
  `_commit_progress` contract into Odoo 18.
- Access declarations still use `ir.model.access` plus `ir.rule`; the audited
  unified `ir.access` model belongs to 20.

Official baseline: [Odoo 18 developer reference](https://github.com/odoo/documentation/tree/18.0/content/developer).
The version-audit reports record precise per-claim evidence and limits.
